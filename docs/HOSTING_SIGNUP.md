# Hugging Face Spaces + Supabase: инструкция (регистрация вместо Oracle)

> Отвечает на `docs/QUESTIONS.md` №6 (вариант выбран пользователем — `DECISIONS.md` №52)
> и №5 (домен: бесплатный поддомен `*.hf.space`).
> Оба сервиса **проверены из сети пользователя 2026-10-08** (curl: 200/отвечает),
> **бесплатны навсегда и не требуют международной карты**.

## 0. Что мы получаем

| | Hugging Face Spaces | Supabase |
|---|---|---|
| Что | Публичный сервер: наш Docker-контейнер (игра целиком) | PostgreSQL в облаке (прогресс детей, аккаунты) |
| Цена | $0 навсегда (CPU Basic) | $0 навсегда (500 МБ БД, 5 ГБ трафика/мес) |
| Адрес | `https://<логин>.hf.space` — наш домен с HTTPS | отдельно, нужен только бэкенду |
| Карта | не нужна | не нужна |
| Деплой | push кода → автосборка | таблицы создаются сами при старте |

Хватает с огромным запасом на класс (30 учеников): 500 МБ БД — это миллионы
записей прогресса, трафик 5 ГБ/мес — сотни тысяч запросов.

⚠️ Space может **засыпать при длительном простое** (редкие визиты) и просыпается
при открытии за ~15–30 секунд. На уроке, когда все заходят — он уже разбужен.

## 1. Регистрация Hugging Face (~5 минут)

1. Открыть **https://huggingface.co** (в твоей сети работает — проверено).
2. Кнопка **Sign Up** → зарегистрироваться через **GitHub** (аккаунт уже есть)
   или по email+паролю. Если по email — подтвердить письмо.
3. Перейти в **Settings → Access tokens** (https://huggingface.co/settings/tokens)
   → **Create new token**:
   - название: `game-deploy`;
   - роль (role): **write**;
   - срок жизни: можно «no expiration» (позже можно отозвать там же).
4. Скопировать токен (начинается с `hf_...`).

⚠️ **Токен — как пароль**: он может управлять твоими проектами на HF.
Храним бережно; если куда-то утечёт — зайти сюда и **Revoke**, выпустить новый.

## 2. Регистрация Supabase (~7 минут)

1. Открыть **https://supabase.com** (в твоей сети работает — проверено)
   → **Start your project** → войти через **GitHub** (это и есть учётка).
2. Если предложат organization — создать (название любое, например `my-org`),
   тариф **Free**.
3. Кнопка **New project**:
   - **Name**: `game-python`;
   - **Database password**: нажать «Generate» и **сохранить** его в надёжном месте;
   - **Region**: **Frankfurt, Germany** — ближе всего к нам (как и было
     выбрано для Oracle);
   - **Create project** (~2 минуты на развёртывание).
4. В левом меню **Project Settings → Database** (или кнопка **Connect** сверху) →
   вкладка **Connection string** → переключить на **Session mode** →
   драйвер **URI**. Скопировать строку вида:

   ```
   postgresql+psycopg://postgres.xxxxxxxx:<пароль>@aws-0-xxxx.pooler.supabase.com:5432/postgres?sslmode=require
   ```

   ⚠️ Именно **Session mode** (не Direct — у него IPv6, не Transaction — он
   обрывает длинные соединения). Если в конце нет `?sslmode=require` — добавить.

## 3. Что прислать мне

1. **HF-токен** (`hf_...`).
2. **Connection string Supabase** (session mode, целиком, с паролем).

Дальше **всё делаю сам**: создам Space `подземелья-python`, запушу код
(репозиторий на GitHub остаётся главным — деплой = обычный `git push`),
задам секреты (`JWT_SECRET` — сгенерирую сам, `DATABASE_URL`, `FRONTEND_URL`),
проверю смоук-тестами по реальному адресу и дам ссылку.

## 4. Технические детали (для протокола)

- **Образ**: `Dockerfile` в корне репозитория (SDK: docker, порт **7860**) —
  один контейнер: nginx (статика React + reverse-proxy `/api` + rate-limit)
  и uvicorn (FastAPI) внутри на `127.0.0.1:8000`.
- **Таблицы**: создаются автоматически при старте (`SQLModel.metadata.create_all`);
  на свежей БД несколько воркеров гонялись — починено advisory-lock'ом
  (`backend/app/db.py`), проверено на пустой PostgreSQL-схеме.
- **Песочница**: `RUNNER_MODE=local` (Docker внутри Space недоступен).
  Изоляция: отдельный процесс, `-I`, свой «чистый» env без секретов, лимиты
  3 с / 256 МБ / 2 CPU, stdin закрыт, **сеть отключена** (в HF Space работает
  Python-заглушка — `DECISIONS.md` №53). Теоретический обход через `ctypes`/
  подпроцессы остаётся — настоящая ядерная изоляция это план п.18.
- **Письма**: пока в `outbox.log` (SMTP не настроен — план п.16),
  `REQUIRE_EMAIL_VERIFICATION=0`. Включим SMTP отдельным шагом.
- **Регистрация**: публичная регистрация создаёт **учителя** (видит только свои
  классы); ученики — только по коду класса. На открытом сервере это ок.

## 5. Дальнейшие деплои

Код остаётся на GitHub. Заготовка авто-деплоя лежит в
[`scripts/deploy-hf.workflow.yml`](../scripts/deploy-hf.workflow.yml) (push в `main` =
пересборка Space ~2 мин). Её нужно **скопировать в `.github/workflows/`** — это
делается только вручную или с GitHub-токеном, у которого есть область `workflow`
(наш текущий токен её не имеет). Чтобы включить:

1. Добавить в GitHub **Settings → Secrets and variables → Actions**:

| Тип | Имя | Значение |
|---|---|---|
| Secret | `HF_TOKEN` | тот же HF-токен (`hf_...`) |
| Variable | `HF_SPACE_REPO` | `логин/podzemelya-python` |

2. Скопировать `scripts/deploy-hf.workflow.yml` в `.github/workflows/deploy-hf.yml`
   (в веб-интерфейсе GitHub: *Add file → Create new file*).

Пока всё это не настроено — ничего не ломается (вручную деплой делаю я скриптом
`HF_TOKEN=... HF_SPACE_REPO=... python3 scripts/deploy_hf.py`).

## 6. Если что-то пошло не так

- Space в состоянии **Building/Ошибка** → вкладка **Logs** на странице Space —
  прислать мне.
- БД недоступна → проверить в Supabase **Settings → Database**, что строка
  именно **Session mode** и `sslmode=require`.
- Забыли токен HF → Settings → Access tokens → создать новый, старый отозвать.
